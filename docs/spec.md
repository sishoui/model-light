## 0. 一句话

一台 ESP32-C3 用 BLE 接收微信小程序下发的**编排序列**，脱机驱动 8 路 WS2812；小程序侧负责编排
编辑、3D 灯板预览与云端备份；云端只做账号与备份，永不参与控制决策。

## 2. 系统拓扑与跨端契约

四个可独立交付的部件。箭头方向表示「谁发起」。

```
                 ┌──────────────────────────┐
                 │ 微信小程序（主包 ≤2 MB）  │
                 │ 编排编辑器 · 3D 灯板预览  │
                 └───┬──────────────────┬───┘
        BLE（GATT，5 特征 + OTA 1 特征） │ HTTPS（JWT）
                     │                  │
        ┌────────────▼───────┐   ┌──────▼─────────────┐
        │ ESP32-C3 固件      │   │ 自建后端 NestJS     │
        │ 编排 NVS · 渲染     │   │ MySQL 8 · Caddy     │
        │ RMT 复用 · OTA 会话 │   │ 账号 · 备份（不解析）│
        └────────────────────┘   └────────────────────┘
```

三条铁律，贯穿所有部件：

1. **设备的 NVS 是编排的唯一真源。** 云端只记录「上次同步时设备上是什么」；任何方向都不允许云端
   自动覆盖设备。
2. **控制权只在 BLE 层判定。** 令牌 + 礼貌交接决定谁能写；后端不参与，不做权限表。
3. **网络不可用时全功能本地可用。** 登录、备份、OTA 都是可失败的旁路，不阻塞 BLE 播放与编辑。

### 2.1 BLE GATT

服务 UUID 基址 `7c9f0000-1b2a-4c3d-9e8f-000000000000`。**单服务，不拆分**——微信多服务枚举要多一次
往返且无收益。

| 特征 | 属性 | 用途 |
|---|---|---|
| `...0001` 命令 | write + writeNoResponse + notify | 令牌请求/授予/心跳、模式切换、工厂重置 |
| `...0002` 实时 | writeNoResponse | 叶子参数，单帧 ≤ 9 B，无 ACK |
| `...0003` 序列块 | writeNoResponse + notify | 编排分片 + ACK/NAK |
| `...0004` 状态 | notify + read | 12 B 全量状态帧 |
| `...0005` 设备信息 | read | 固件版本、协议版本、能力位图、设备 ID |
| `...0006` OTA | write + writeNoResponse + notify | 固件字节，独立通道 |

所有写一律走 **writeNoResponse**（iOS 上 `write` 会排队导致吞吐暴跌）；可靠性由应用层 ACK 保证。
通知只用 **notification**，不用 indication。设备信息额外镜像到标准 DIS `0x180A`，供非小程序调试工具读。

**chunkSize 由手机侧每次连接现定**，不写进协议、不跨会话保存：

| 平台 | 策略 |
|---|---|
| iOS | 固定 **20 B**。`setBLEMTU` 在 iOS 是空操作；超长写会静默无回调，**不能靠写失败信号重试，只能靠 ACK 判活** |
| Android | 请求 247 → 185 → 20，取 `getBLEMTU()` **实测 ATT_MTU − 3**（247 → **244**，不是 185） |

### 2.2 分片帧与可靠传输

```
Frame := cmd(1) + seq(2, LE) + payload(n)
```

| cmd | 名称 | 方向 | payload |
|---|---|---|---|
| `0x01` | `START` | 手机 → 设备 | `totalLen(2) + payloadVersion(2) + protoMajor(1) + protoMinor(1) + crc32(4)` = 10 B |
| `0x02` | `DATA` | 手机 → 设备 | 原始编排字节 `[seq * chunkSize, ...)` |
| `0x03` | `FIN` | 手机 → 设备 | 无 |
| `0x04` | `RESET` | 手机 → 设备 | 无 |
| `0x05` | `ACK` | 设备 → 手机 | `ackUpTo(2) + nakMask(2) + status(1)` = 5 B |
| `0x06` | `NAK` | 设备 → 手机 | 同 ACK，`status` 非 0 |

- `seq` 从 0 递增，16 位回绕。**单片不带 CRC**——BLE 链路层已有 CRC，20 B 窗口下再扣 2 B 会让 iOS
  吞吐掉约 35%；误码由结尾整份 CRC32 捕获。
- `nakMask` 的 bit i 表示 `ackUpTo + 1 + i` 片缺失，最多回看 16 片。
- **窗口 8 片**在途；每收满 8 片或距上次 ACK ≥ 200 ms 发一次 ACK。
- 退避 200 → 400 → 800 ms（封顶），连续 3 次无 ACK 视为失败，手机发 `RESET`；手机侧单次传输总超时 30 s。
- 设备侧收到的半份编排**立即丢弃**，不写 NVS；手机重连后从头重传。

**原子提交**（`FIN` 后依次校验）：长度匹配 → CRC32 匹配 → 编解码成功 → 像素归属互斥 → 版本兼容。
全部通过才整体写 NVS；任一失败回 `NAK`，**上一份编排保持原样，播放不中断**。
NVS 落盘**去抖 2 s**，避免连续调参写穿 flash。

### 2.3 实时参数通道

```
Realtime := pin(1) + groupIndex(1) + stageIndex(1) + layer(1) + paramIdx(1) + valueLen(1) + value(valueLen)
```

最短 6 B，颜色 8 B，整数/枚举 7 B。**永远单帧，不分片。** `layer`：0 = background，1 = dynamic。
只改叶子参数，设备只覆盖本轮渲染，不动 NVS 编排。

- 寻址失败**静默丢弃**（无 ACK 通道），错误只走状态帧错误码。
- 节流 **50 ms（20 Hz）**，小程序侧**最新值覆盖**，窗口内中间值丢弃。
- 空闲回落见 §2.6。

### 2.4 优先级规则

| 情形 | 规则 |
|---|---|
| 回放中收到实时包 | 立即进实时模式；回放时间轴**在后台继续跑，不暂停** |
| 编排传输中收到实时包 | 实时包照常处理，不阻塞渲染；传输走独立 ACK 队列 |
| 实时模式中收到 `FIN` | 提交照常完成，渲染仍停留实时模式直到超时；新编排生效于超时之后 |
| 非令牌连接发实时包或编排写 | 拒绝，状态帧报 `0x01` |

### 2.5 连接生命周期

```
[广播] ──► [可连接] ──createBLEConnection──► [已连接·未鉴权]
                                                    │ 订阅状态帧
                                                    ▼
                                              [已连接·只读] ◄── 无令牌的一切连接
                                                    │ REQ_TOKEN
                                                    │ 设备 PROBE 现持有者，5 s 内 YES/NO
                                                    ▼
                                              [持有令牌] ──心跳 10 s──► 30 s 无心跳释放
                                                    │ 断连
                                                    ▼
                                              [挂起·保留 60 s] ──重连──► [持有令牌]
                                                    │ 超时 ──► [已连接·只读] / [可连接]
```

- 并发连接上限 **4**，第 5 条 `createBLEConnection` 失败。
- **鉴权**：无 PIN、无配对密钥，物理邻近即入口。防熟人用**来访模式**（flags bit1）：开启后只能改编排，
  不能工厂重置。
- **令牌是控制权不是身份。** 交接 = 新连接 `REQ_TOKEN` → 设备向持有者 `PROBE` → 5 s 内 `YES`/`NO`/超时。
  无持有者时第一个 `REQ_TOKEN` 直接获得，不走 PROBE。
- 重连退避 1 / 2 / 4 / 8 s 封顶，无限重试，切片后台或用户取消时停。重连流程：订阅状态帧 → 读设备信息
  → 令牌仍在保留期内则直接恢复（无需 PROBE）→ 恢复调参界面。
- 小程序回前台（`onAppShow`）用缓存 `deviceId` 直连，不重扫。

### 2.6 断连即回放

**BLE 一断，设备立刻退出实时模式回到回放，不保留最后一帧。** 实时模式 3 s 无包同样自动回落。
选中某个颜色从来不是用户想要的效果。

### 2.7 扫描与发现

- 广播名 `ML-XXXX`（4 位十六进制，跨账号稳定）。
- manufacturer data（厂商 ID 2 B + payload 7 B = 9 B）：`[0..1]` 厂商 ID（测试期 `0xFFFF`）、
  `[2]` major、`[3]` minor、`[4..5]` 能力位图、`[6]` 运行状态（0 回放 / 1 实时 / 2 传输中 / 3 错误）。
  广播总长约 21 B，31 B 限制内。
- 扫描只能按服务 UUID 过滤（微信限制），其余过滤在小程序侧做。
- **不缓存 `deviceId`**：iOS 上它会在系统蓝牙重启或忽略设备后变化；每次会话重扫，按广播名匹配。

### 2.8 版本与能力协商

- 协议版本 `major.minor` 各 1 B，随广播与 `START` 携带，连接后可从设备信息特征读。
- `major` 相同：兼容，未知字段忽略，未知灯效降级静态色。
- `major` 不同：**互相只读**。小程序禁用编辑、提示升级，但**播放照旧**。
- 能力位图 2 B：bit0–11 = 12 支灯效（顺序同 §2.10 表）、bit12 = OTA、bit13 = 来访模式、bit14–15 保留。
- 旧固件遇新小程序：缺的灯效禁用并提示升级，不阻止已有编排运行。新固件遇旧小程序：未知字段忽略，
  保存时提示「降级保存可能丢失 X 个未知字段」。

### 2.9 状态帧与错误码

12 B 全量：`mode(1) + arrangementVersion(2) + arrangementCrc32(4) + brightnessLimit(1) + tokenHolder(1)
+ errorCode(1) + temperature(1) + flags(1)`。

- `mode`：0 回放 / 1 实时 / 2 传输中 / 3 错误。
- `tokenHolder`：0 无令牌 / 1 本连接持有 / 2 其他连接持有。
- `temperature` 仅诊断，不参与限亮。`flags`：bit0 正在传输，bit1 来访模式。
- 变化立即发，否则每 5 s 心跳全量；全量设计让断连期间的丢失自动补齐，无需增量掩码。
- 错误码持续显示，直到下一次成功操作或 30 s 后清零。

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| `0x00` | 正常 | `0x08` | flash 失败（OTA） |
| `0x01` | 未持令牌 | `0x09` | 镜像无效（OTA） |
| `0x02` | 编排校验失败（CRC / 解码） | `0x0A` | CRC 不符（OTA） |
| `0x03` | 分片缺口超限 | `0x0B` | 版本被拒（OTA） |
| `0x04` | NVS 写失败 | `0x0C` | 待续传（OTA） |
| `0x05` | 编排区已满 | | |
| `0x06` | 灯组像素重叠 | | |
| `0x07` | 固件版本不符（major 不同） | | |

### 2.10 编排线格式

字段边界由 #3 定死，传输由 §2.2 定死。

```
Arrangement := { version(u16), payloadVersion(u16), pins: Pin[8] }
Pin         := { length(u8), name(UTF-8 ≤16B), groups: Group[] }
Group       := { ranges: Range[], stages: Stage[] }
Range       := { start(u8), end(u8), reverse(bool) }
Stage       := { durationMs(u16), fadeInMs(u8), layers: Layer[] }
Layer       := { role(u8), effectId(u16), paramBytes[] }
```

**身份与寻址**：设备 = 广播名；引脚 = 0–7 整数（固定 8 个，不可增删，可配名）；灯组 = `(pin, groupIndex)`；
阶段 = `(pin, groupIndex, stageIndex)`；层 = `background` | `dynamic`。

**像素归属**：灯组 = 引脚内一个或多个 `[start, end)` 区间 + 可选 `reverse`。**一颗灯珠只能属于一个灯组**，
重叠则拒绝整份编排。**未被覆盖的像素渲染为黑色**（不留残影）。引脚长度由小程序写入并存设备，设备不做推断。

**阶段与合成**：总时长 = 各阶段之和，灯组独立循环，互不等待。合成**覆盖式**（动态层逐像素盖背景层）。
切换**硬切**，阶段可选 `fadeInMs`（0 = 硬切）。

**时钟**：单个 FreeRTOS 任务驱动全局帧时钟，目标 **40 FPS**（输出层上限 76 FPS，余量充足）。每个灯组用
`clockMs % groupTotalMs` 定位阶段与偏移；同一时钟取模，天然不漂移。

### 2.11 灯效清单（第一版 12 支）

灯效 = `{ id, name, role, params }`，`role` 决定能放进哪一层。参数类型：`color`(RGB)、`int`(带 range)、
`enum`、`bool`、`speed`。**灯效实现在固件**；schema 在小程序与固件各写死一份（后端只存不解析），握手比对
版本。固件遇未知 id 降级为静态色（取 `primaryColor`，缺省白）。

| 层 | id | 名称 | 参数 |
|---|---|---|---|
| bg | `bg.solid` | 纯色 | color |
| bg | `bg.gradient` | 双色渐变 | colorA, colorB, reverse |
| bg | `bg.breath` | 呼吸 | color, periodMs, minLevel(0–100) |
| bg | `bg.rainbowLow` | 慢速彩虹 | saturation, brightness, periodMs |
| bg | `bg.flame` | 火焰底色 | colorHot, colorCold, intensity |
| dy | `dy.comet` | 流星拖尾 | color, tailLen, speedMs, reverse |
| dy | `dy.scan` | 扫描线 | color, width, speedMs, direction |
| dy | `dy.blink` | 闪烁 | color, onMs, offMs, duty(0–100) |
| dy | `dy.rainbowFlow` | 流动彩虹 | saturation, brightness, speedMs |
| dy | `dy.sparkle` | 随机闪点 | color, density(0–100), decayMs |
| dy | `dy.pulse` | 脉冲扩散 | color, periodMs, width, fromCenter |

## 3. 固件（ESP32-C3FH4）

### 3.1 输出层

C3 的硬件天花板是 **2 路并行**：RMT TX 只有 2 通道且无 DMA（FIFO 48 symbol/通道），GPSPI 仅 1 路可用，
I2S 无 LCD_CAM / 并行模式。8 条独立灯带的可行形态只有「2 路 × 4 轮复用」或「串成一条链」。

**裁决：2 RMT × 4 轮复用**，实测上限 76 FPS（8 路真并行需 S3/P4，串成 1×800 链只有 41 FPS）。
复用细节**藏在输出层**，上层只见 8 条逻辑灯带。led_strip v3.1.1 每个 handle 一路，`refresh_async()`
无双缓冲，**双缓冲与轮换要自研**。

**必须自研的**：双缓冲 + 异步刷新、复用调度与各带 latch 时序、GATT 参数协议、重连状态回灌。

### 3.2 基座

**ESP-IDF 5.4+ + NimBLE + 自研输出层。** Arduino-ESP32 只带 Bluedroid，单核上 `loop()` 与 RMT 补喂 ISR
会打架。FastLED 的 C3 路径只有 2 通道且 I2S 并行被硬关；Adafruit_NeoPixel 软件延时在 BLE 负载下会闪。

SRAM：800 颗 RGB 帧缓冲 2400 B，双缓冲 4800 B；扣掉 NimBLE + FreeRTOS + 驱动后实际剩 **~150–220 KB**。
双缓冲够用，前提是开机一次性 `heap_caps_malloc(MALLOC_CAP_INTERNAL)` 分配，避免碎片。

### 3.3 硬件

- 满亮 800 颗 = 48 A，30% = 14.4 A → **5 V 20 A 电源 + 固件默认限亮 30%**。
- 每 ~100 颗 / 2 A 一个注入点，每带 470–1000 µF 大电容。
- **3.3 V 数据低于 WS2812B 的 V_IH(3.5 V)，必须电平转换**（74HCT245 / SN74LVC1T45），首像素串 330–470 Ω。
- 共地星形接在电源处；C3 单独 3.3 V LDO + 10 µF/100 nF。

### 3.4 分区与 OTA

- **分区表不留 factory**，双 1.5 MiB 槽（`ota_0@0x10000` / `ota_1@0x190000`），1956 KB 数据区。
- **分区表与 bootloader 不能 OTA 改，v1 首次烧写就必须定型。**
- 开 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`；不做 anti-rollback，降级用 NVS `min_allowed_version` 管。
- OTA 需持令牌。

**OTA 铁律**：

| 项 | 规则 |
|---|---|
| 渲染 | **暂停编排渲染**（flash 擦写让 RMT ping-pong 中断延迟，灯带花屏）；灯效改 5 FPS 低亮呼吸蓝；暂停 40 FPS 帧任务 |
| 他连接 | 只读不踢 |
| 令牌交接 | 拒 `BUSY` |
| 实时包 / 编排写 | 拒收并**明回** `BUSY`（不静默丢） |
| 进度 | 状态帧 `mode=2` 外加 1 B 进度，1% 节流 |
| 会话持久化 | NVS 存 `{sha256 前 16 B, totalLen, bytesWritten, crc32}`，**每 16 KB 且 4 KB 对齐落盘**，掉电最多重传 16 KB |
| 提交顺序 | 整份 CRC32 → `esp_ota_end()` → 版本校验 → `esp_ota_set_boot_partition()` → 重启；任一步失败即 `esp_ota_abort()`，不改 boot partition |
| 重启后 | 令牌必空；靠固件版本号变化判定「刷完了」 |

**OTA 通道与命令**：走独立特征 `...0006`，复用 §2.2 的帧结构与窗口 ACK，载荷换成固件字节。命令
`OTA_BEGIN(0x20)` / `QUERY(0x21)` / `DATA(0x22)` / `COMMIT(0x23)` / `ABORT(0x24)` / `RESUME(0x25)`。
`OTA_BEGIN` 带 `image_size + sha256 + app_version + crc32`。指纹不符静默作废旧会话。

**OTA 的超时规则与编排不同**：per-ACK 3 s，20 次无进展转「待续传」而非失败，**无会话总超时**（iOS 的
700 KB 要 2.5–4 分钟，续传不可砍）。续传**以设备回 `OTA_QUERY` 为准**，不以手机记忆为准。

## 4. 小程序

- **主包预算 ≤ 2 MB。** 3D 用 **xr-frame**（基础库内置，不吃主包，内置 bloom + 自定义 shader）。
  threejs-miniprogram（r108 停更）、Canvas 2D、web-view（无 BLE API，个人号不可用）均落选。
- **不能逐帧推像素**：iOS 一次连接事件一包时 2400 B 帧约 210 ms ≈ 4.8 FPS。参数包模型是唯一可行路径。
- **不支持后台 BLE**，所以灯必须脱机自主运行。
- **BLE 客户端**照 §2.1–2.9 实现；写串行不并行（并行写会失败）；`writeType: 'writeNoResponse'` 需基础库
  ≥ 2.22.0。
- **交互骨架**：第一屏设备列表 → 设备详情 → 8 个引脚（可命名）→ 引脚内多段灯组 → 灯组内多阶段 →
  每阶段双层灯效 + 时长。选灯组像素时已被占用的灯珠置灰、不可选。
- **3D 预览**：只做**灯板**形态，不做 3D 折线；**一次只看一个引脚**（≤ 100 颗）；每颗渲染成 WS2812
  **5×5×1.6** 长方体，按 `rowWidth`（默认 10）铺满；蛇形 / 从左到右可选。位置由
  `(ledCount, rowWidth, layout)` 参数化推导，**不存坐标**。预览**只看不可编辑**，颜色按编排 + 帧时钟
  **推演**；设备状态帧只驱动顶栏徽标与提示条。帧率 30 / 60 可选，默认 30。布局存云端备份 + 本地缓存，
  **不进设备**。
- **云端调用**：连上后**自动上推**，下拉恢复**必须手动**；备份失败不阻塞 BLE。

## 5. 后端

详细端点、表结构、鉴权见 [`spec-backend.md`](spec-backend.md)。要点：

- 单机 `docker compose`（NestJS + MySQL 8 + Caddy）；HTTPS + ICP 备案域名是唯一外部前置。
- 账号 = openid 一行，首次 `wx.login` 静默建号，未登录全功能本地可用；JWT 7 天 + refresh 30 天旋转
  （存 sha256）。
- 设备**无归属、无共享、无角色、无踢人**；云端只是「谁 push 过」的记账，任何登录用户都能读写任意合法
  `ML-XXXX` 的备份。
- 备份 = 编排 TLV 不透明字节（只验 CRC32 与 64 KiB 上限，不解析结构）+ 结构化元信息（8 引脚命名长度、
  3D 布局、固件版本）+ `last_good` 可回退一步；两张表 `devices` / `device_backups`。
- 无 CAS / 409，`rev` 只用于「你落后了」的提示。

## 6. 切片与依赖

按**端**切，不按功能切——功能切片会让每张票都横跨三端，而三端之间只隔着 §2 一个接口。

```
固件骨架（GATT + 输出层）──┬──> 编排 TLV 存取 ──┬──> 渲染与 12 支灯效 ──> 令牌与交接
                            │                     │
                            └──> OTA 会话 ────────┘
小程序 BLE 客户端 ──> 编排编辑器 ──> 3D 灯板预览
后端账号与备份 ──> 小程序云端同步
```

**三块可完全并行开工**：固件骨架、小程序 BLE 客户端、后端账号与备份。它们的共同前置只有 §2 契约，而
契约已经定死。各自跑通后再对接。

**tracer bullet 顺序**：固件骨架（一条灯带播静态色）→ 小程序 BLE 客户端（能连、能读状态帧）→ 编排 TLV
单阶段单层落盘 → 渲染出这一阶段 → 编排编辑器最小闭环 → 令牌与礼貌交接 → OTA → 3D 预览 → 云端备份。
