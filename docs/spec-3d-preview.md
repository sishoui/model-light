# 规格：3D 预览（灯板模式）

本文件是 [3D 预览：渲染选型、灯带线段场景模型与标注交互](https://github.com/sishoui/model-light/issues/5) 这张票的产出：一份可交接给后续 agent 直接实现的规格，不含可运行代码。

原票的问题是「灯带发光线段」怎么做。讨论过程中方案被整体改写：**不做 3D 折线，只做灯板**。原因记录在文末「作废的决定」，领域词汇见 `GLOSSARY.md`。

---

## 1. 结论摘要

| 项 | 结论 |
|---|---|
| 渲染技术 | **微信 xr-frame**（基础库内置，不吃 2 MB 主包） |
| 一次显示 | **一个引脚**的灯珠 |
| 灯珠形状 | **WS2812 长方体**，正面 5×5 mm、有厚度 |
| 排列 | 每行 `rowWidth` 颗（默认 10），**实际颗数**铺满；可选蛇形 / 从左到右 |
| 预览内容 | **只看**，不可编辑；编辑在预览外的操作区 |
| 渲染颜色 | **推演**：小程序按编排 + 全局帧时钟自己算，不等设备 |
| 帧率 | **可调**，用户选 30 / 60，默认 30 |
| 布局数据 | 云端备份 + 本地缓存，**不进设备 NVS** |

## 2. 渲染技术选型（裁决）

### 候选与实际依据

| 方案 | 主包成本 | 发光表现 | 逐帧几何更新 | 结论 |
|---|---|---|---|---|
| **xr-frame** | **0**（随基础库下发，只有自己的 xml/ts 计入包体） | 内置 `bloom` post-process，可自定义 GLSL `Effect` | `scene.createGeometry` + `uploadVertexBuffer`，官方示例即粒子系统 | **选它** |
| threejs-miniprogram | 适配器 ~588 KB（未压缩）+ 打包进去的 three 本体，数百 KB 到 1 MB+ | r108 时代，`UnrealBloomPass` 不在适配器里，要自己接 | 可用，但要自己维护老版本 | 落选：官方适配器 **2021-04 停更，停在 three r108** |
| Canvas 2D 伪 3D | 0 | 需要多次 `stroke` 叠光晕；且 2D canvas 逻辑上限 1365×1365，安卓超大画布崩溃 | 不适用 | 落选：还要靠 setData 之外的方式画，收益低 |
| web-view | 0 | WebGL 可用性未经权威验证 | — | **否决**：web-view 只拿到 JSSDK 白名单接口，**没有 BLE**；且需业务域名 + ICP 备案 + 域名根目录校验文件，**个人类型小程序不能用 web-view** |

### xr-frame 的硬约束（写进实现注意事项）

- 基础库最低 **2.27.1**，推荐 2.32.0；iOS 8.0.29+ / Android 8.0.30+。
- **全应用同一时刻只能有一个 xr-frame 组件**，组件内**只有一个顶层 `xr-scene`**，且**不能与普通 `<view>` 混写**（UI 要走同层渲染 / HUD）。
- **不支持自定义 render graph**：post-process 只能用内置的（`bloom` / `blur` / `fastblur` / `tone` / `vignette` / `fxaa`），要更复杂的发光只能烘进 shader。
- 自定义几何：一个 geometry 只有**一个 SubMesh**；必须 `setBoundBall` / `setBoundBox`，否则视锥剔除会误杀；顶点缓冲要等 mesh 上了 GPU 之后才能 `uploadVertexBuffer`。
- 透明材质 `renderQueue` 要 > 2500。
- 开发者工具**默认关 GPU 加速**；WebGL 在**真机调试里不工作**，只能用**真机预览**。

## 3. 场景数据模型（草案）

### 3.1 实体

```
DeviceLayout            // 一台设备的 3D 布局，云端备份 + 本地缓存，不进设备
  deviceId: string
  version: uint32       // 本地/云端编辑版本号
  rowWidthDefault: uint8  // 默认 10，可被单个引脚覆盖
  pins: PinBoard[8]

PinBoard                // 一个引脚的灯板
  pin: uint8            // 0–7
  ledCount: uint8       // 1–100，实际接了多少颗 = 渲染多少颗
  rowWidth: uint8       // 默认 10
  layout: enum          // 'row-major-snake' | 'row-major-left-right'，默认 'row-major-left-right'
```

### 3.2 为什么不存 3D 点序列

灯珠位置完全由 `(pin 的 ledCount, rowWidth, layout)` 推导，不需要存坐标。参数化推导比存坐标更稳：

- 改颗数、改行宽、切换蛇形，位置自动重算，不会出现"存了 300 个点改了颗数对不上"。
- 布局文件极小（每引脚 4 个字节量级），云端备份和本地缓存都没压力。

### 3.3 位置推导（写进实现）

设颗数为 `N`、行宽为 `W`、灯珠边长 `S = 5`（等价单位）、格间距 `G = 2`（`S + G` 为节距）：

```
索引 i (0-based)，从 0 开始：
  row = i / W
  colRaw = i % W
  col = (layout == snake && row % 2 == 1) ? (W - 1 - colRaw) : colRaw

  x = col * (S + G)
  y = -row * (S + G)      // y 向下，第一行在顶部
  z = 0                   // 板面 Z 方向，朝默认相机
```

- **实际颗数铺满**：`N = 60`、`W = 10` 就是 6 行满行；不会出现空行。
- **不画空位**：未接的格子不渲染任何东西，用户一眼看出这条灯带接了多少颗。
- **蛇形 vs 从左到右**：只影响奇数行的列顺序，不改变总行数。
- **行宽可配**：每引脚覆盖 `rowWidthDefault`，存在 `PinBoard.rowWidth`，跟 `ledCount` 同一条消息写入设备（即使设备只用它算像素区间，不用它画图）。

### 3.4 默认相机

进入预览时**自动框选实际灯板**：按 `N` 算出的外接框（`rows = ceil(N / W)`，宽度 `W * pitch`，高度 `rows * pitch`），相机放在板面正前方、距离使外接框刚好占满视口 80%。「复位」回到这个自适应视角。

## 4. 渲染方案

### 4.1 灯珠

- 形状：**WS2812 封装**。正面 **5×5 mm 的正方形**，有厚度，**不是**侧发光里的长方形。厚度建议 `S : T = 5 : 1.6`，即 5×5×1.6。
- 数量：**实际颗数**，上限 100。最坏 100 个长方体，xr-frame 在帧率预算内非常轻松。
- 每个长方体**用同一份几何**，位置/颜色走实例化（`Effect` 里的实例属性）或逐节点，实现时按性能实测选；100 个的数量级下两者都可，优先实例化。

### 4.2 颜色来源：推演，不等设备

预览颜色由小程序**按编排 + 全局帧时钟自己算**，与设备是否连接无关：

```
t = (now - t0) mod groupTotalDuration
stage = 按 stage 时长累加定位
color_i = 背景层(i) 被 动态层(i) 覆盖
```

- 设备侧的 12 B 状态帧**只用来显示徽标**（连接状态、编排版本号是否一致、是否处于实时模式），**不驱动颜色**。
- 好处：没连设备也能看；设备在别处被改，版本号不一致时预览照常演。
- 「手机和实物不一致」的观感问题由下一条的提示条处理。

### 4.3 两种显示范围

- **当前灯组**：只有该灯组覆盖的灯珠上色，其余灯珠暗（保留位置，不删）。
- **整条引脚**：该引脚全部灯珠按各自灯组的编排上色，完整还原实物。

切换在控制条的「显示范围」分段控件里，实时生效，不重置相机。

### 4.4 边界标记

**只在「正在编辑某个灯组的像素区间」时**，给该区间首尾两颗灯珠加一个更亮的描边（如环 / 高亮框），用于核对"第 40–80 颗"。纯播放时不画，避免干扰。

### 4.5 帧率与降级

- 帧率**用户可调**：30 / 60，默认 **30**。
- 说明：设备侧全局帧时钟是 40 FPS，但推演按时间取模，与预览帧率无关，**60 FPS 不会更"准"**，只是更顺、更耗电。规格里写清楚，界面不必警告。
- 达标线：**≥ 30 FPS**（用户选 60 时按所选值，不达标则回落 30）。
- 降级阶梯（自动，每次降一档，不回弹，除非重进预览）：
  1. 降低后处理：关 bloom 的 `is-hdr`，再不行关 bloom；
  2. 降低几何：长方体分段数减半；
  3. 兜底：整板换成平面色块（不画厚度）。
- 循环用 `canvas.requestAnimationFrame` / xr-frame 的 `scene` tick 驱动，**不要**把逐帧数据走 `setData`；`onHide` / `onUnload` 停循环。

## 5. 与实时调参的联动

预览是**推演**，不订阅实时包，因此不存在"两边不同步"的渲染错位。真正要处理的是**观感预期**：

- 顶栏常驻一条窄提示条（不遮 3D、不降场景亮度），在以下任一情况显示：
  - 未连接设备；
  - 编排版本号与设备状态帧不一致；
  - 设备处于实时模式（`mode = 2`）。
- 提示条文案区分三种原因，不要混成一句"未同步"。不降场景亮度 —— 降亮会让"看到的就是实物亮度"的直觉失效。
- 实时调参面板与预览的关系：面板在**操作区**，改参数后在**下一次预览 tick** 就反映在灯板颜色上（推演用同一份编排），不额外走 BLE 就不会有延迟差。

## 6. 交互线框（v1）

### 6.1 页面结构

xr-frame 不能与 `<view>` 混写，所以 **3D 区是页面上方一块固定比例的 xr-frame 画布**，下方是普通区域放控制条（v1 不碰 HUD）。

```
┌───────────────────────────────┐
│ 顶栏：设备名 · [连接徽标]       │
│ 提示条（条件出现，一行窄条）     │
├───────────────────────────────┤
│                               │
│        xr-frame 灯板           │  ← 固定比例，自适应框选
│      （旋转 / 缩放 / 复位）     │
│                               │
├───────────────────────────────┤
│ 引脚 pill ▾（可收起）           │
│  [0][1][2][3][4][5][6][7]     │
├───────────────────────────────┤
│ 灯组 chip（横滑）               │
│  ◀ [头部] [底座] [装饰] ▶      │
├───────────────────────────────┤
│ 显示范围  [当前灯组 | 整条引脚]  │
│ 排列      [蛇形 | 从左到右]     │
│ 帧率      [30 | 60]           │
│ 播放 / 暂停                     │
└───────────────────────────────┘
```

- **引脚 pill 可收起**：收起后只剩一行"引脚 0 · 头部"和展开箭头，给 3D 区让位。
- **一次只显示一个引脚**：切换 pill 立即换板，**重置到该引脚的自适应视角**。
- **灯组 chip**：只在引脚内展开；选中一个后「显示范围」才有意义。
- **行宽配置**不进预览页，在**引脚编辑页**（与 `ledCount` 一起写入）。

### 6.2 相机

- 单指拖拽旋转、双指缩放。
- 「复位」按钮回到该引脚的自动框选视角。
- 不做预设视角（俯视/正视），留到 v1.1：需要一套"按设备推荐视角"的数据，现在没有。

### 6.3 视觉样式

- 背景 `#0b0b10`，灯珠未上色时为深灰 `#3a3a48`。
- 板面无网格线，只有灯珠本身构成的阵列；用户靠灯珠间距读行列。
- 灯珠发光靠 `bloom`，阈值偏高，避免整板糊成一片。

## 8. 作废的决定

讨论中一度成立的方案，**不要**再按它们实现：

1. ~~灯带 3D 折线（Strip Segment）+ 沿线弧长等分画像素~~ —— 改为灯板网格。
2. ~~一次性显示 8 条引脚（24,000 颗球）~~ —— 改为一次一个引脚。
3. ~~球体几何~~ —— 改为 WS2812 长方体。
4. ~~Canvas 2D 伪 3D / three.js~~ —— 见第 2 节。
5. ~~布局数据进设备 NVS~~ —— 云端备份 + 本地缓存。
6. ~~每引脚 300 颗~~ —— 上限 **100 颗**。
7. ~~预览内可选像素区间~~ —— 预览**只看**，选择在操作区。
